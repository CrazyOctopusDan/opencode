## 合并冲突处理建议

- 先按上表定位文件，再按“关键改动点”逐项核对，不按整文件覆盖。
- 若上游也新增登录链路：保留“接口不变 + CLI 本地 token + TravelSky 单 provider”的约束。
- CLI 登录门禁必须先于受保护请求：旧 token 先预检，失败即清理并重新登录；带 `--session` 时 session 校验必须携带新 Bearer。
- CLI 模型选择必须使用规范 `travelSky` provider id；`provider_next` 只作为兜底来源，不能优先把小写 `travelsky` 写入当前模型、recent 或 prompt 参数。
- CLI 登录后即使 Provider 服务已经在登录前初始化，prompt 执行前也必须能用当前 Tempo session 刷新 TravelSky 模型策略，不能因为内部 Provider 状态过旧而报 `Model not Found: travelSky/<model>`。
- Desktop 模型弹窗依赖 `/provider.connected` 过滤可选模型；`llm/list` 返回 TravelSky 模型时必须同步把 `travelSky` 放入 `connected`，不能只出现在 `all` 中。
- 公司 `/llm/list` 的行式 payload 中，`id` 是数据库记录 id；合并时必须保留 `model` 作为模型标识、`title` 作为显示标题，不能用 `id` 或不存在的 `name` 字段推断模型族。
- 模型族 prompt 路由必须保留企业别名：`dsv4`、`dsv4-flash` 走 DeepSeek prompt；`Qwen*` 走 Qwen prompt；公司数据库 id 不参与 prompt 路由。
- 若上游调整 TUI 命令注册：优先保留 `/connect` 与 `/models` 的 TravelSky 固定入口行为。
- 若上游新增 metric 统计：优先保留“runLoop 完成态单次添加生成记录 + `/ai/data/api/record/saveGeneration` 平铺字段（含 `modelName`、`adoptedLines`、Integer 行数字段、Desktop/CLI 各自 `toolName`）+ 生成记录 qaid 成功返回后按最终文件 diff 调 `/ai/data/api/record/addAdoption`”的语义。
- agent 时代采纳口径是最终文件 diff：`adoptedLines` 取新增行，`deletedLines` 取删除行，`adoptedContent` 固定为空字符串。
- 文件修改统计只用于聚合生成行数和语言，不上传 diff 原文；第一版 `other.v1/v2` 只保留在设计文档中作为历史口径，不再发送给当前生成记录接口。
- 非 git 目录也必须能统计生成行数：内部 snapshot 对比根限定为当前目录，不能因为没有 `.git` 返回全 0，也不能把对比范围扩大到 `/`。
- 若上游调整 Desktop 登录或 provider SDK：优先保留 `debug_tempo.auth_expired` 触发的模型列表恢复链路；恢复成功后必须使用新建 client 重试，恢复失败必须清理登录态并回到登录页。
- 若上游调整全局 SDK、fetch 注入或 event stream：必须保留本地 sidecar 401 后 `auth.recover()` 并重试原请求一次的能力，尤其是 `/session/.../prompt_async` 发送消息链路。
- 若上游调整启动同步或 session 列表加载：`GET /session?directory=...&roots=true` 遇到 local 401 时应通过单飞恢复和 SDK 重试处理，不能为每个目录分别弹 401 toast。
- 若上游调整 Desktop 存储：记住我密码只能通过 Electron `safeStorage` 密文保存；加密不可用、解密失败或 IPC 不可用时只能填用户名，不能保存或恢复明文密码。
